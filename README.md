# CodePulse

A release-debugging tool: it ingests commits, pull requests, CI runs, deployments, and service-health events for a repository, merges them into one timeline, and -- when a service goes unhealthy -- ranks the recent commits and pull requests most likely to be the cause, using a deterministic scoring function whose output you can check by hand.

Full write-ups: [ARCHITECTURE.md](ARCHITECTURE.md) (how it's put together) · [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md) (why, for each non-obvious choice) · [BENCHMARKS.md](BENCHMARKS.md) (measured throughput, latency, and accuracy, with the exact command to reproduce them).

## Stack

Next.js (App Router) + TypeScript · PostgreSQL + Drizzle ORM · a plain Node worker process (no queue framework) · `@octokit/rest` for GitHub ingestion · `prom-client` for Prometheus metrics · Vitest (unit/integration/failure-path/benchmark-smoke tests) + Playwright (e2e) · Docker Compose for Postgres.

## Setup

Requires Node 20+, Docker, and (optionally, for real GitHub ingestion) a GitHub personal access token.

```bash
git clone <this-repo> && cd CodePulse
cp .env.example .env
npm install
docker compose up -d db
npm run db:migrate
npm run db:migrate:test   # separate database the test suite truncates freely
```

Or all at once: `make setup` (installs deps, starts Postgres, runs both migrations).

## Running it

```bash
npm run dev      # the app: http://localhost:3000
npm run worker   # separate terminal: ingests from GitHub + recomputes correlation for open incidents
```

The worker only does GitHub ingestion if `.env` has `GITHUB_TOKEN` and `GITHUB_REPO` (`owner/name`) set -- without them it still runs, just skipping that step, and correlation still works against whatever data you've posted to the ingestion APIs.

### Seeing it work without a GitHub token

```bash
npm run seed   # wipes the app DB, writes a synthetic-but-structurally-realistic dataset (see BENCHMARKS.md)
```

Then open http://localhost:3000 -- the dashboard lists open incidents; click one to see the ranked candidate commits/PRs and their score breakdown. (`npm run seed`'s data is explicitly synthetic, generated by `scripts/lib/dataset.ts`, and is only ever written to your own local/dev database -- never presented as real activity.)

### Or drive it by hand with curl

```bash
# Register a repo and a service (a service owns a set of file-path patterns within the repo)
curl -X POST localhost:3000/api/repos -d '{"owner":"octo","name":"widgets"}' -H 'Content-Type: application/json'
curl -X POST localhost:3000/api/services -d '{"repoId":1,"name":"web","pathPatterns":["src/**"]}' -H 'Content-Type: application/json'

# Report a deployment and a health check going "down"
curl -X POST localhost:3000/api/deployments -H 'Content-Type: application/json' -d \
  '{"serviceId":1,"externalId":"d1","toSha":"abc123","status":"succeeded","startedAt":"2026-01-01T11:55:00Z","completedAt":"2026-01-01T11:56:00Z"}'
curl -X POST localhost:3000/api/health-events -H 'Content-Type: application/json' -d \
  '{"serviceId":1,"externalId":"h1","status":"down","observedAt":"2026-01-01T12:00:00Z"}'
# -> {"eventId":1,"duplicate":false,"incidentId":1}

curl -X POST localhost:3000/api/incidents/1/correlate
```

Then visit `/incidents/1`.

## Features

- **GitHub ingestion** (`src/ingestion/github-adapter.ts`) -- pulls commits, PRs, and CI runs/jobs for a tracked repo, resumable via per-source checkpoints (`ingestion_checkpoints` table), rate-limit-aware.
- **Deployment and service-health ingestion APIs** (`POST /api/deployments`, `POST /api/health-events`) -- webhook-shaped, idempotent, zod-validated.
- **Release timeline** (`GET /api/timeline/[repoId]`, `/repos/[id]`) -- commits, PRs, CI runs, deployments, and health events merged into one chronological feed.
- **Deterministic regression-correlation engine** (`src/correlation/`) -- ranks candidate commits/PRs for an incident by time proximity, changed-file overlap with the affected service, CI signal, and PR risk. No LLM in the scoring path.
- **Incident drill-down with evidence** (`GET /api/incidents/[id]`, `/incidents/[id]`) -- the full ranked list with each candidate's score breakdown, not just a single verdict.
- **Prometheus metrics** -- `GET /api/metrics` (app process), `:9091/metrics` (worker process): ingestion events/sec, ingestion errors, worker lag, worker failures, correlation duration, API request latency, GitHub rate-limit remaining.

## Testing

```bash
npm test               # unit + integration + failure-path + benchmark-smoke (Vitest)
npm run test:unit       # pure functions only -- no database
npm run test:integration
npm run test:e2e        # Playwright; starts its own dev server if one isn't already running
npm run test:coverage
```

Or `make test` / `make test-e2e`. All 4 categories the spec asks for exist as separate directories under `tests/`: `unit/` (pure correlation-engine logic, no I/O), `integration/` (ingestion + API routes against a real Postgres), `failure/` (duplicate webhooks, out-of-order events, GitHub rate limiting, worker/checkpoint restart, malformed input, DB rollback, missing commit ancestry, partial CI data -- one test file per case), and `benchmark/` (a small-scale smoke test that the synthetic-data generator and the correlation engine still agree with each other; the actual benchmark numbers come from `npm run benchmark`, not from an assertion in the test suite).

## Benchmarking

```bash
npm run build && npm start &   # or npm run dev, in another terminal
npm run benchmark
```

Seeds 25,000+ events, runs the real correlation engine against 200 seeded incidents with known causes, and load-tests the API. See [BENCHMARKS.md](BENCHMARKS.md) for the full methodology and the last measured results.

## CI

`.github/workflows/ci.yml`: lint + typecheck → test (against a Postgres service container) → build → e2e. Runs on every push and PR.

## Repository layout

```
CodePulse/
  app/                        Next.js routes: pages + API handlers (app/api/*)
  src/
    db/                       Drizzle schema, migrations, client
    ingestion/                GitHub adapter, deployment/health ingestion, checkpoints
    correlation/               types, ancestry, score, rank (pure) + load, compute (DB-touching)
    worker/                    poll loop + its own metrics endpoint
    metrics/                   the shared prom-client registry
    lib/                       zod validation, timeline/incident query helpers, API latency wrapper
  scripts/
    lib/dataset.ts              synthetic-data generator shared by seed + benchmark
    seed-synthetic.ts           `npm run seed`
    benchmark.ts                 `npm run benchmark`
    migrate.ts                   `npm run db:migrate[:test]`
  tests/
    unit/  integration/  failure/  benchmark/  e2e/
  docker-compose.yml           Postgres (+ optional Prometheus)
  Makefile
```
